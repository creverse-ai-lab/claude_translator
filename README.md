# claude_translator

Claude Code가 답변을 터미널에 **표시하기 직전**에 가로채서, 로컬 Ollama의
`gemma4:e2b`로 자연스러운 한국어로 다시 쓰는 훅입니다.

화면에 보이는 글자만 바뀝니다. 저장되는 대화 기록과 Claude(모델)가 읽는
내용은 그대로입니다.

## 크기와 요구 사항

| 항목 | 크기 |
|---|---|
| 이 저장소 (코드 전체) | **약 45KB** (8개 파일) |
| 기본 모델 `gemma4:e2b` 디스크 | **7.2GB** (`ollama pull` 시 1회 다운로드) |
| 모델 상주 RAM (로드 시) | **약 7.3GB** (실측, num_ctx 4096) |
| 추론 중 추가 RAM | 거의 없음 (상주분에 포함) |

- OS: macOS / Linux
- `python3` — 표준 라이브러리만 사용, 추가 패키지 설치 없음
- [Ollama](https://ollama.com) — 로컬에서 실행 중이어야 함 (`ollama serve`)
- Claude Code **2.1.235 이상** (`MessageDisplay` 훅 이벤트가 있는 버전)

모델은 첫 번역 요청 때 RAM에 올라가고 `keep_alive`(기본 30분) 동안
상주하다가 자동 반납됩니다. `/translator off` 상태에서는 모델을 아예
호출하지 않으므로 RAM을 쓰지 않습니다. 즉시 내리려면 `ollama stop gemma4:e2b`.

## 설치

```bash
git clone <이 저장소> claude_translator
cd claude_translator
./install.sh
```

`install.sh` 가 하는 일:

1. `python3` / `ollama` 확인. `config.json` 에 적힌 모델이 없으면 `ollama pull`
2. `~/.claude/settings.json` 에 `MessageDisplay` 훅을 **병합** 등록
   — 기존에 있던 다른 훅과 설정은 건드리지 않고, 수정 전 백업을
   `settings.json.before-translator.bak` 으로 남깁니다
3. `/translator` 슬래시 커맨드를 `~/.claude/commands/translator.md` 에 설치
4. 번역 상태를 `on` 으로 설정

재실행해도 중복 등록되지 않습니다(기존 항목을 교체). 저장소를 다른 위치로
옮겼으면 `install.sh` 를 다시 실행하면 경로가 갱신됩니다. 적용은 **새
세션부터**입니다 (훅과 슬래시 커맨드는 세션 시작 때 로드됨).

제거는 `./uninstall.sh` — 훅 등록, 슬래시 커맨드, 상태 파일만 지우고
저장소와 다른 훅은 그대로 둡니다.

## 어떻게 동작하는가

Claude Code의 `MessageDisplay` 훅 이벤트를 사용합니다. 이 이벤트는 답변이
스트리밍되는 동안 새로 완성된 줄 묶음마다 실행되며, 훅이 돌려준
`displayContent`가 원래 글자 대신 화면에 표시됩니다. **표시 전용**이라
대화 기록과 모델 입력은 바뀌지 않습니다. 스트리밍 중에는 화면이 비어 있고,
마지막 실행에서 완성본이 한 번에 나타납니다.

### 파이프라인 (기본값: dispatch 모드)

> 탐지는 파이썬이, 소형 모델은 쪼개진 마이크로 태스크만, 종합은 다시 파이썬이.

```
Claude 답변 (완성본)
  1. 코드 마스킹        ── ```블록·`인라인`을 [[CODE_n]]으로 보호
  2. 정규식 교정        ── 정답이 하나인 번역투·중의 표현 (모델 불필요)
  3. 탐지 (파이썬)      ── 영어어근+한국어어미 표현(robust한) / 긴 문장 / 문체 이탈
                            (bullet은 항목당 1태스크 — 목록 통째보다 ~5배 빠름)
  4. 분배 (소형 LLM)    ── 발견 1건 = 마이크로 태스크 1건, 병렬 실행
                            · 표현: "robust한 → 자연스러운 한국어로" (few-shot)
                            · 문장: "이 문장만 나눠라 / 합니다체로 바꿔라"
  5. 검증 (파이썬)      ── 태스크별 형식·숫자·자리표시자 검사, 불합격 = 원문 유지
  6. 종합 (파이썬)      ── 통과한 결과만 원래 위치에 치환 + 조사(이/가·으로/로) 교정
  7. 복원              ── 코드 되돌리기, 행동 항목 모음 부착
```

모델이 전체 글을 쥐지 않으므로 요약·누락·구조 파괴가 **구조적으로 불가능**
합니다. 모델의 실수는 해당 스팬 하나에 갇히고, 검증에 걸리면 그 스팬만
원문으로 남습니다.

용어 병기는 기본적으로 **Claude 말버릇(영어 어근+한국어 어미)만** 대상입니다
— `robust한` → `견고한(robust)`, `idempotent하지 않아서` →
`멱등적이지(idempotent) 않아서`. `mutex`, `failover` 같은 일반 영어 용어는
개발자가 그대로 읽는 게 빠르므로 건드리지 않습니다 (전면 병기를 해봤더니
소음이었습니다). 모든 용어를 병기하려면 `gloss_terms: "all"`.

`mode: "rewrite"` 로 바꾸면 이전 방식(조각 단위 전체 다시 쓰기)으로
동작합니다. dispatch가 못 하는 문장 전반의 다듬기가 필요할 때 씁니다.

## 설정값 (`config.json`)

| 키 | 기본값 | 뜻 |
|---|---|---|
| `enabled` | `true` | 상태 파일이 없을 때의 기본 on/off |
| `ollama_url` | `http://127.0.0.1:11434` | Ollama 서버 주소 |
| `model` | `gemma4:e2b` | Ollama 모델 이름 |
| `keep_alive` | `"30m"` | 모델 RAM 상주 시간. RAM이 아쉬우면 `"5m"` 또는 `"0"` |
| `temperature` | `0.0` | 다시 쓰기라 0 고정 권장 |
| `num_ctx` | `4096` | 컨텍스트 길이 (조각 1,200자 + 프롬프트에 충분) |
| `request_timeout_sec` | `150` | Ollama 요청 1건의 제한 시간 |
| `min_chars` | `200` | 이보다 짧은 답변은 손대지 않음 |
| `max_chunk_chars` | `1200` | 조각 하나의 최대 길이 |
| `min_chunk_chars` | `400` | 이보다 짧은 마지막 조각은 앞 조각에 합침 |
| `parallel_chunks` | `3` | rewrite 모드의 동시 조각 수 |
| `gloss_terms` | `slang` | 병기 범위. `slang`: `robust한` 같은 영어어근+한국어어미만 (기본). `all`: 모든 영어 용어. `off`: 안 함 |
| `parallel_tasks` | `6` | dispatch 모드의 동시 마이크로 태스크 수 |
| `min_output_ratio` | `0.6` | 결과가 원문의 60% 미만이면 실패 처리 |
| `max_retries` | `1` | 조각 실패 시 재시도 횟수 |
| `mark_fallback` | `true` | 원문을 그대로 둔 조각에 사유를 표시 |
| `collect_actions` | `true` | 행동 문장을 문서 끝에 복사해 모아줌 |
| `actions_min` | `2` | 행동 문장이 이 개수 이상일 때만 모음 블록 생성 |
| `mark_chunks` | `false` | 조각 경계에 `---` 표시 |
| `keep_original` | `true` | 비교 모드: 원문과 결과를 위아래로 둘 다 표시 |
| `part_wait_sec` | `3.0` | 마지막 실행이 형제 조각을 기다리는 시간 |
| `mode` | `dispatch` | `dispatch`: 탐지→분배→종합. `rewrite`: 조각 단위 전체 다시 쓰기 |
| `prompt_file` | `prompt.en.md` | rewrite 모드가 쓰는 프롬프트 파일 |
| `debug` | `false` | 로그·조각 덤프 기록 |

모든 키는 `CT_<대문자키>` 환경변수로 덮어쓸 수 있습니다.
예: `CT_MODEL=gemma4:e2b claude`, `CT_ENABLED=0 claude`, `CT_DEBUG=1`.

## 켜고 끄기 — 스킬처럼 쓰기

훅은 항상 실행되지만 상태 파일을 먼저 봅니다. 꺼져 있으면 모델 호출 없이
원문을 즉시 통과시킵니다 (지연 0).

| 방법 | 명령 |
|---|---|
| 세션 안에서 | `/translator on` · `/translator off` · `/translator status` · `/translator` (토글) |
| 터미널에서 | `python3 hooks/translate_display.py --on` (`--off`, `--toggle`, `--status`) |

상태는 `~/.claude/message-display-translator/state` 에 저장되며 모든 세션에
공통 적용됩니다. 변경은 다음 답변 표시부터 반영됩니다.
"평소엔 끄고 필요할 때만 켜기"로 쓰려면 한 번만 `/translator off` 해두세요.

## 비교 모드

기본값(`keep_original: true`)에서는 원문과 결과를 둘 다 보여줍니다.

```
── 전 · Claude 원문 ────────────────────────────

커넥션 풀 고갈로 인한 요청 타임아웃 다발.

── 후 · gemma4:e2b ─────────────────────────────

커넥션 풀이 고갈되어 요청이 시간 초과되는 일이 많이 발생했습니다.
```

결과만 보려면 `keep_original` 을 `false` 로 바꾸거나 `CT_KEEP_ORIGINAL=0`.

## 내용을 잃지 않기 위한 장치

작은 모델은 문장을 통째로 빠뜨리거나 왜곡합니다. 다섯 겹으로 막았습니다.

1. **코드 보호** — ```` ``` ```` 블록과 백틱 안 글자는 `[[CODE_n]]`
   자리표시자로 바꿔서 보냅니다. 모델이 코드를 건드릴 수 없고, 복원 시
   코드 펜스 앞 줄바꿈도 보장합니다.
2. **숫자 보존 검사** — 원문의 숫자(타임스탬프, 수량, 버전 포함)가 결과에서
   하나라도 사라지면 그 조각은 실패 처리 후 재시도.
3. **자리표시자·길이 검사** — 자리표시자가 사라졌거나 결과가 원문의 60%
   미만이면 실패 처리 후 재시도.
4. **원문 대체** — 재시도까지 실패하면 그 조각은 Claude 원문 그대로 둡니다.
   구멍이 뚫리는 대신 번역이 안 된 채로 남습니다 (`mark_fallback` 이 사유 표시).
5. **조각내기 무손실 검증** — 조각 분할 자체가 글자를 잃거나 복제하지 않았는지
   매번 대조하고, 어긋나면 분할을 포기하고 통째로 처리합니다.

reasoning 계열 모델이 사고 과정을 유출하는 경우(`<think>...</think>`)도
자동으로 제거합니다.

## 설계 원칙: 판단을 모델에서 코드로

실측으로 도달한 원칙 두 개가 이 구조를 만들었습니다.

1. **정답이 하나로 정해지는 규칙은 전부 파이썬 정규식으로.** 소형 모델은
   긴 프롬프트의 규칙을 놓치고, 금지 예시를 주면 오히려 그 패턴을 배워
   왜곡합니다 (`501번이 6번으로` → `501분의 6으로`).
2. **모델에는 전체 글이 아니라 쪼개진 태스크를.** "전체를 다시 쓰되 일부만
   고쳐라"(선택적 편집)는 소형 모델이 감당 못 하는 과제 형식입니다 —
   1B급은 복사 아니면 환각의 이분법이었고, 2B급도 반복 많은 긴 조각에서
   요약 충동을 보였습니다. 태스크를 "용어 1개", "문장 1개"로 좁히면
   실패가 국소화되고 검증이 정밀해집니다.

파이썬 정규식 층이 처리하는 것 (모델 도착 전, 비용 0):

| 종류 | 예 |
|---|---|
| 이중 피동 | `보여집니다` → `보입니다`, `되어집니다` → `됩니다` |
| `N배 줄었다` (중의적) | `12배 줄었다` → `12분의 1로 줄었다`. `배` 없으면 안 건드림 |
| 불필요한 대명사 | `당신의`, `우리는`, `우리가` 삭제 |
| 고정 번역투 | `~인 것으로 확인됩니다` → `~입니다`, `개선이 이루어졌습니다` → `개선했습니다`, `요구됩니다` → `필요합니다` |
| im-not-ai 이식분 | `~를 통해` → `~로`(조사 자동 선택), `X를 가지고 있다` → `X가 있다`, `~에서의` → `~에서`, `본질적으로` 삭제 |
| 정보 없는 첫 문장 | `조사해봤습니다. 결론부터 말하면` 삭제 후 결론부터 시작 |

번역투 패턴 일부는 [im-not-ai](https://github.com/epoko77-ai/im-not-ai)의
분류표(A군)에서 가져왔습니다. 단 그쪽의 "AI 티 제거" 규칙(병기 삭제, 불릿
해체, 문장 길이 불균일화)은 이 도구의 목적(빠른 이해)과 반대라 이식하지
않았습니다.

**행동 항목 모음**: `~하세요`, `~필요합니다`, `~권합니다`, `~주십시오` 문장이
2개 이상이면 문서 끝에 그대로 복사해 모아줍니다 (요약이 아니라 복제 — 본문에도
남음, 코드 블록은 제외). `~해야 합니다`가 설명 문장까지 잡는 오탐이 있습니다.

## 성능과 모델 비교 (실측, Apple Silicon 24GB)

같은 입력(번역투 샘플 360자, 장애 보고서 977자)으로 4개 모델을 비교했습니다.

| 모델 | 디스크 | 상주 RAM | 360자 | 977자(4조각) | 판정 |
|---|---|---|---|---|---|
| **`gemma4:e2b`** (기본값) | 7.2GB | 7.3GB | 15.2초 | 42.8초 | 용어 풀어쓰기 적극적 (핵심 기능). 가끔 유사어 왜곡 (`미봉책`→`임시방편`) |
| `gemma3:1b` | 0.8GB | 1.15GB | 2.5초 | 4.4초 | **부적합** — rewrite에선 무변경 복사, dispatch에선 용어 12건·문장 3건 태스크 전부 검증 탈락 (`volatile`→`변동성` 오역 등). 안전장치 덕에 출력은 원문 그대로 |
| `phi4-mini-reasoning` | 3.2GB | 3.7GB | 21.1초 | 121.5초 | **부적합** — 한중 혼종 환각 (`과부탈`, `연결池`) |
| `kanana-2-3b` (Q4) | 2.2GB | 2.4GB | — | — | **부적합** — 출력 붕괴 (`))))` 반복) |

- 두 gemma 모두 숫자 35종·코드 3블록·표 7행·제목 6개를 전부 보존했습니다.
- 용어 풀어쓰기(`race condition` → `경쟁 조건(race condition)`)는 모델의
  일이며, 1B급은 이걸 못 합니다. 전문용어 10종이 든 샘플에서 `gemma3:1b` 는
  한 글자도 바꾸지 않았고 `gemma4:e2b` 는 10종 전부 풀어썼습니다.
- 참고: 5KB(2,868자, 6조각) 입력은 `gemma4:e2b` 기준 87.7초였습니다.
  RAM·속도가 우선이면 `model` 을 `gemma3:1b` 로 바꾸세요 — 정규식 교정과
  안전장치는 그대로 작동하고, 용어 풀어쓰기만 포기하게 됩니다.
- 병렬 3조각 설정이지만, 로컬 GPU 메모리에 따라 Ollama가 사실상 순차
  처리할 수 있습니다.

번역되는 동안 화면에는 아무것도 보이지 않다가 한 번에 나타납니다.

## 제한 사항

- **스트리밍이 안 보입니다.** 답변이 끝나고 번역이 끝날 때까지 화면이
  비어 있다가 한 번에 나타납니다. 구조상 불가피합니다.
- 200자 미만 답변은 그대로 통과합니다 (`min_chars`).
- 소형 모델의 한계로, 판단이 필요한 규칙들(지시어를 실제 대상으로 치환,
  빠진 주어 채우기)은 성공률이 낮습니다.
- 행동 항목 수집에 오탐이 있습니다 (설명 문장의 `~해야 합니다`).
- 훅 등록은 전역(`~/.claude/settings.json`)이라 모든 프로젝트에 적용됩니다.
  특정 프로젝트에서만 쓰려면 등록 JSON을 그 프로젝트의
  `.claude/settings.json` 으로 옮기세요.

## 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| 답변 끝에 "Ollama에 연결하지 못해..." | `ollama serve` 가 안 떠 있음. 실행 후 다음 답변부터 정상 |
| `/translator` 가 Unknown command | 커맨드는 세션 시작 때 스캔됨. 새 세션을 열면 인식 |
| 답변이 유난히 느림 | 첫 요청의 모델 콜드 로드(수 초) 또는 긴 답변. `/translator status` 로 모델 확인 |
| 원문이 뒤섞여 보임 | 조각 검증 실패로 일부가 원문 폴백된 것. `mark_fallback` 이 사유를 표시함 |
| 뭐가 잘못됐는지 보고 싶음 | `CT_DEBUG=1` 로 실행 후 `~/.claude/message-display-translator/debug.log` 확인 |

되돌리기: `./uninstall.sh`, 또는 설치가 남긴 백업으로 복원 —

```bash
cp ~/.claude/settings.json.before-translator.bak ~/.claude/settings.json
```

## 변경 이력

### 2026-08-26

- **dispatch 파이프라인 도입 (기본 모드)** — 파이썬이 고칠 곳을 탐지하고,
  소형 모델에는 스팬 단위 마이크로 태스크만 분배하고, 결과를 파이썬이
  검증·병합. 모델이 전체 글을 쥐지 않아 요약·누락이 구조적으로 불가능.
  기존 방식은 `mode: "rewrite"` 로 유지.
- **용어 병기 범위 축소** — 전면 병기(`mutex` → `뮤텍스(mutex)`)는 소음이라
  제거. 기본값은 Claude 말버릇(영어 어근+한국어 어미)만 교체:
  `robust한` → `견고한(robust)`, `idempotent하지` → `멱등적이지(idempotent)`.
  `gloss_terms` 설정으로 `all`/`off` 선택 가능.
- **bullet 단위 태스크** — 목록은 항목당 1태스크로 병렬 처리 (통짜 대비
  실측 4.7배). 문체 판정은 산문 기준으로 바꿔 개조식 bullet이 판정을
  뒤집지 않게 함.
- **few-shot + 파이썬 형식 조립** — 모델은 한국어 답만 내고 `한국어(원어)`
  조립은 코드가 담당. 병기 정확도 9/12 → 12/12, 속도 8배.
- **병기 치환 뒤 조사 자동 교정** — 받침 계산으로 이/가·을/를·으로/로·은/는
  ·과/와 재선택.
- **im-not-ai 번역투 패턴 이식(A군)** — `~를 통해` → `~로`(조사 자동 선택),
  `X를 가지고 있다` → `X가 있다`, `~에서의` → `~에서` 등. AI 티 제거용
  규칙(병기 삭제·불릿 해체)은 목적이 반대라 이식하지 않음.
- **모델 실측 비교** — gemma4:e2b(기본) vs gemma3:1b vs phi4-mini-reasoning
  vs kanana-2-3b. 1b는 rewrite에선 복사기, dispatch에선 전 태스크 검증
  탈락. phi4는 한중 혼종 환각, kanana는 출력 붕괴로 부적합 판정.
- **지시 언어 실측** — 마이크로 태스크는 한국어 지시(품질 우세), rewrite
  긴 프롬프트는 영어 지시. 속도는 재측정 결과 두 언어 동일.
- **폭주 방지** — 문장 태스크에 여유 상한(자수x6+48), reasoning 모델의
  `<think>` 유출 자동 제거.

### 2026-08-25
